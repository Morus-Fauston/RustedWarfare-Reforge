# Owned Phase V sandbox

These INI, JSON, Hjson and mixed-format packages combine existing self-owned public fixtures. They contain no extracted original-game content. The default installed PC scene is `scenarios/phase-five-json.json`; its map, complete content closure and independent contract travel with the application.

The 1200 by 800 controlled map has dry land left of x=600 and water to the right. Player one starts with only a command center and 30000 credits. Its ordinary production creates the builder; the builder constructs land, mech, air and sea factories. Paid mech and sea upgrades retain their factory identities. Normal production obtains c_tank, mechGun, the ordinary LAND development variant mechHeavyMissile, helicopter and heavyBattleship. All five coexist at tick 15000, followed by normal Move, Stop and Attack calls and mixed ground/air/sea combat through tick 22000.

The twelve charges total 26350. The surviving initial center earns 4.5 credits every ten ticks, so exact credits are 10400 at tick 15000 and 13550 at tick 22000. Contracts independently require the declared births, upgrades, ledger, firing sources and target deaths. Short cases cover the initial center-to-builder chain; long cases collect the complete Core and Session chains. These are self-behavior fixtures, not original-game starting conditions, timing standards, performance measurements or device evidence.

Source declarations and PNGs are reused from `three-format-economy/construction`, `heavy-mech-production`, `helicopter-production` and `naval-production` under the existing self-owned fixture terms. Unit images remain in their unit directories to preserve the original relative references. Builder v7 explicitly lists all four supported construction types; prices, rates, movement, weapons and factory exits retain their existing finite profiles. The mixed package alternates INI, JSON and Hjson declarations through the same content model.

The full scenario is the common menu/Core/Session seed. A selected bad input disables Start; it must be repaired and checked again. Windows automation uses the default content entry for the JSON scene, with only evidence and placeholder-visual overrides, and retains the existing window ownership, input, layout and bounded-wait guards. This does not replace a separate empty-argument installation smoke test or real platform evidence.

Before each Build, the builder makes an ordinary final eastward approach within its existing construction range; the fixed building birth boundaries include that preparation. The Core runner uses `declared-tank` for the same finite tank declaration accepted by the content package. For the flying enemy, `position` is the displayed click point (750,630), while `targetGroundPosition` independently fixes its core ground point (750,650). The history comparator still requires the accepted attack to bind the exact living enemy ID and ground point; no numeric tolerance is added.
